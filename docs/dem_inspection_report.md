# DEM 文件体检报告

## 0. 分析范围与方法

- 分析对象：data/dem/DEMn_1m.tif 及其伴随文件。
- 分析日期：2026-09-03。
- 本报告是只读数据体检，不是 DEM 修复、Reader 或 TerrainMapper 实现。
- 使用 rasterio 1.5.1（GDAL 3.12.4）读取 GeoTIFF 元数据并分块扫描基础像元；
  使用 tifffile 读取 TIFF IFD/GeoTIFF 标签。
- 最小值、最大值、均值、标准差、计数和 NoData 统计基于基础影像全量分块扫描；

- A：文件明确提供（影像或伴随元数据中的原始声明）；
- B：可由 Raster 几何/像元扫描计算得到；
- C：文件无法可靠确定（不能用文件名或经验补猜）。

## 6. CRS / EPSG / WKT（A）

## 8. Raster affine transform 与空间范围（A/B）

Affine transform 六个核心系数：

~~~
a =  1.0
b =  0.0
c =  473506.78215896204
d =  0.0
e = -1.0
f =  4335988.239580579
~~~

矩阵形式：

~~~
| 1.00,  0.00, 473506.78215896204 |
| 0.00, -1.00, 4335988.239580579  |
| 0.00,  0.00, 1.00               |
~~~

- 像元外边界左上角（origin）：(c, f) = (473506.78215896204, 4335988.239580579)。
- pixel width：1.0 m。
- pixel height：1.0 m（e=-1 表示向南递增的行方向）。
- 像元中心规则：

~~~
x_center(i) = c + (i + 0.5) * a
y_center(j) = f + (j + 0.5) * e
~~~

- 左上角像元中心：(473507.28215896204, 4335987.739580579)。
- 右下角像元中心：(500183.28215896204, 4299175.739580579)。

根据 transform、width、height 计算出的空间范围（像元外边界）：

| 项目 | 值 |
|---|---:|
| xmin / left | 473506.78215896204 |
| xmax / right | 500183.78215896204 |
| ymin / bottom | 4299175.239580579 |
| ymax / top | 4335988.239580579 |
| width × pixel width | 26,677.0 m |
| height × pixel height | 36,813.0 m |

一致性检查：

~~~
(xmax - xmin) - width  × pixel_width  = 0.0 m
(ymax - ymin) - height × pixel_height = 0.0 m
~~~

范围是由 GeoTIFF affine transform 的外边界与像元行列数计算得到的（B），不是数据
提供方另行声明的模型计算区域。

.tfw 内容为：

~~~

0
0
-1
473507.282159
4335987.739581
~~~

它给出左上像元中心坐标；与影像 transform 的中心坐标相差约 4e-7 m 以内的舍入误差。

## 16. 结论分类汇总

### A. 文件明确提供

- 唯一主文件为 GeoTIFF/GTiff。
- 26,677 × 36,813、单波段、float32。
- NoData=-32767、波段单位字段=metre、VerticalUnitsGeoKey=EPSG:9001、AREA_OR_POINT=Point。
- 内嵌投影 WKT 及 EPSG authority 4548。
- 1 m 像元、无旋转的 affine transform、LZW 压缩和 overview 信息。

### B. 可由 Raster 几何/像元计算

- 空间范围、像元中心公式和范围一致性误差。
- 有效/NoData 数量比例、统计值、负值比例。
- NoData footprint、内部空洞和最大连续 run。
- north-up、axis-aligned、无旋转。
- 若与 V1.0 目标网格比较，1 m DEM 相对 30～100 m 网格属于“更细”的候选关系；
  这是基于已测像元大小和已冻结网格范围的工程分类，不是文件声明。

### C. 文件无法可靠确定

- DEM/DTM/DSM 类型。
- 像元高程的业务统计含义（AREA_OR_POINT=Point 本身不足以完成该解释）。
- 垂直基准、垂直 CRS、椭球/大地水准面关系。
- 数据生产、平滑/滤波/填洼/重采样历史。
- 水体、河道、建筑物、道路的处理方式。
- 水平/垂直精度、误差模型和适用尺度。
- NoData 的物理含义及是否代表测量缺失、范围外或质量无效。

## 18. 对后续 V1.0 输入规范的影响（不执行处理）

- terrain.file 可以引用该 TIFF；在本次文件体检时没有修改 config.yaml。

- NoData 策略应保持 error：由于存在大量 NoData 和内部空洞，映射层不能用边缘值、
  0 或自动外推填充。
- 主影像像元为 1 m，而当前 V1.0 目标计算尺度为 30～100 m；按冻结规则，未来在
  元数据确认覆盖/对齐后，auto 将把“DEM 更细”分类为 area_weighted_mean。
  这里只是规则分类，不是本轮执行的重采样。
- Raster 的范围由其 transform 得到，不能反过来决定模型 xmin/xmax/ymin/ymax。
- 在没有数据准备层之前，不能判断它与某个模型网格是否对齐，也不能生成
  terrain_elevation[j, i]。
