日期：2026-10-19。状态：总体方案v0.2。用户已要求补充后分批实现；**首批合同/预检/内置模板实施范围已冻结在[07工作单](07_r1_authorized_work_order.md)**，其余产品仍依分批验收推进。

本轮只读取演示包、当前模型和业务代码并编制方案；不建新表、不改业务代码、不导入截图数值、不启动工程计算。配套：[接口流程](02_integration_contract.md)、[实施工作单](03_implementation_handoff.md)。

主聊天仍只负责方案、指挥与验收；生产代码交原实施窗口。[05管理与新建](05_management_and_creation.md)和[06历史来源与模板](06_builtin_dispatch_sources.md)补齐最新要求：下边界不是用户必填，未知保持显式未知；内置历史事件不冒充完整计算资料。

## 1. 结论

不按截图拆成五套互不关联的数据表。建立一条共同的数据链：

**预演场景 → 不可变场景版本 → 计算任务 → 执行尝试 → 已校验结果集 → 五个页面的查询视图。**

关系库保存业务对象、输入快照索引、运行状态、汇总指标、过程曲线、风险明细、避险方案和产物索引。完整NetCDF、逐帧网格、瓦片及三维场景资源保留在受控文件/对象存储，数据库持有其版本、地址和校验摘要。不是“所有数据都塞进一个JSON”，也不是“每格每时刻全部展开成数据库行”。

首期优先让页面展示**同一次运行的可追溯数据**，没有真实来源的指标返回缺项；不能为填满页面而从截图反造人口、损失、流场或撤离路线。

## 3. 身份与版本，先约定清楚

| 标识 | 含义与约束 |
| --- | --- |
| tenant_id / project_id | 数据归属和权限范围，由后端身份上下文确定；不信任前端自由传值 |
| scenario_id | 可计算预演场景的业务主键；与旧文档plan_id不同。前端可仍称“方案” |
| scenario_version_id | 不可变输入版本；改边界、雨量、初值、糙率、范围或数据版本必须生成新版本 |
| run_id | 对特定版本的一次计算请求；人工重算生成新run，不覆盖旧run |
| attempt_id / attempt_no | 同一run因技术故障重试的执行尝试；结果不能被较旧attempt回调覆盖 |
| script_id | **脚本执行标识，不是代码版本**；平台由后端派发attempt前唯一生成并持久绑定，worker原样回传；默认沿用北京时间YYYYMMDD加Unix纳秒时间戳。旧单机CLI仍可显式传入 |
| result_set_id | 一次校验/发布的不可变结果产品集合；五页固定读取它，不各自找“最新” |
| asset_snapshot_id / dataset_version_id | 人口、道路、村界、房屋、避难点等数据快照；重算风险不得偷偷换底数 |
| evacuation_revision_id | 基于某结果集和资产快照的避险方案版本，独立于水动力结果 |

已有本地workflow的 `run_id` 与 `script_id` 同值。平台对接必须设置显式映射：`platform_run_id → attempt_id → script_id/local_run_id`，不能把平台run_id塞入现有日志run_id字段，造成与script_id冲突；旧产物不改名、不改摘要。代码版本、依赖版本、引擎参数摘要单独保存。

业务主键沿用现有ASSIGN_ID等约定，接口中的Long ID用字符串，避免JavaScript精度丢失。所有外键关联同时验证租户/项目归属。

## 5. 建议数据模型

以下为**逻辑表及建议表名**，实施前与业务现有命名、迁移版本及租户拦截器对齐。不提供可直接对生产库执行的DDL。

这不是一次性要求新建下述所有表。R1先落场景/版本、run/attempt、result_set/artifact、最小指标/过程线及审计关联；stage/frame等可在满足索引和查询约束时作为受控明细实现。风险、结论编辑、避险版本在对应阶段才落库；可靠消息设施存在时复用，不重复造outbox。物理拆分以实际查询和事务边界为准。

共有要求：业务主键、tenant/project、创建/更新者及时间、逻辑删除/修订字段沿现有规范；所有表/列中文COMMENT。发布结果原则上不可原地更新，修订生成新版本。字符串枚举有白名单；数值要求有限；缺失值用NULL和原因，不用0替代。

| 建议新增对象 | 核心字段与唯一性 | 用途 |
| --- | --- | --- |
| bbs_flood_rehearsal_scenario | name、region集合、source_document_plan_id、current_version_id、业务状态 | 计算场景，不重复旧文档预案 |
| ..._scenario_version | scenario_id、version_no、input_manifest/hash、origin、duration、engine、rule/data版本、统计policy | `(scenario_id,version_no)`唯一，冻结后不可改 |
| ..._input_series / ..._input_point | version_id、对象ID、quantity、role、unit、datum、temporal_policy；time_s/value/quality | 序列与点分离；时间严格递增、重复拒绝；大输入文件可用manifest引用 |
| ..._run | version_id、idempotency_key/hash、state、requested_products、selected_result_set_id、row_version | 租户内幂等键唯一；重算与重试分开 |
| ..._attempt / ..._stage | run_id、attempt_no、script_id、lease_token、code/environment/input摘要、阶段/错误/心跳 | run+attempt_no唯一；script绑定明确，防旧执行者覆盖 |
| ..._result_set | attempt_id、manifest/schema/hash、quality/provenance、publication_state、coverage | 仅校验通过后发布；固定统计版本 |
| ..._artifact | result_set、product/variable、mesh/region、格式、URI、sha/size、CRS/datum、范围/NoData | 存文件索引，不存每格每帧的海量行；相对对象键且不暴露磁盘路径 |
| ..._frame | result_set、frame_index、time_s、instant、artifact引用、quality | 帧号及时间唯一、按manifest定义；不得缺帧冒充完整 |
| ..._metric | result_set、scope、frame或aggregation、metric_code、value、SI_unit、status、reason、policy | 防止同名指标不同口径混用；只有目录允许的metric_code入库 |
| ..._series / ..._series_point | result_set、对象、变量、role、unit/datum；time_s/value/quality | 小规模断面/站点/工程过程线；不能当网格场表 |
| ..._depth_band_stat | result_set、scope、frame/全程口径、边界、面积及资产相交量、coverage | 分级严格不重叠，分级和总体面积闭合 |
| ..._exposure | result_set、asset_snapshot、asset_type/id、相交量、受影响指标、到达区间、覆盖状态 | 村庄/耕地/道路/房屋/人口，不用名称作主键 |
| ..._conclusion | result_set、模板/版本、引用metric/event ID、文本、复核状态 | 摘要中的每个数有出处，窗外说法可检查 |
| ..._evacuation_revision / ..._allocation / ..._route | result_set、资产快照、父版本、计划/审批状态、转移单元、目的地、人数、路线/风险 | 人工方案版本；设计容量/可用容量/当前占用分开 |
| ..._audit_link | tenant/run/attempt/script_id、原hydro batch_id、摘要 | 将原G1审计绑定本次运行；禁止未授权批次关联 |
| ..._publication_outbox | 事务事件ID、run/attempt、expected_version、处理状态 | 若已有可靠任务/消息设施可复用，不另引入重型平台 |

指标表是受控字典，不是任意EAV垃圾桶。核心查询列关系化；完整输入/证据JSON作为快照保留。共用资产和安置点主数据优先复用业务库，只有时点快照/结果关系是本轮新增。

### 索引、类型及部署

- 查询索引围绕 `(tenant_id,scenario_id,created_at)`、`(run_id,attempt_no)`、`(result_set_id,scope,frame_index)`、`(result_set_id,asset_type,asset_id)`、系列+time_s；外键查询列配索引，不给每个JSON字段盲目建索引。
- 普通物理数值使用double并校验有限/范围；金额和精确配额按业务要求DECIMAL；人口数若是空间加权估计需保存估计值/方法，不能伪装整数精确人数。
- 模型/结果包保存带时区瞬时和相对秒；原始时间原点保留、UTC归一化。业务LocalDateTime按既有空格格式传输，另带timeZone，后端转换到模型ISO8601合同；不得将ISO的T格式直接提交现有LocalDateTime DTO。前端按Asia/Shanghai显示，未知事件时间仍NULL；精确计算时间以time_s和原点为准，不以格式化显示串运算。
- 优先沿用业务现有文件服务和异步执行设施；首期单受控worker+数据库任务队列可满足时，不强制新增消息中间件。
- PostgreSQL先验收。金仓兼容模式、空间扩展、JSON类型/索引和驱动需单独验证；不把PostGIS当金仓默认能力。公共合同不强制JSONB/PostGIS，空间能力可由独立GIS处理器产生可查询结果。
- 旧G1 v2没有租户归属：仅适用于现有单租户开发验证。共享多租户生产发布前必须补显式所有权迁移/映射和访问门禁；旧无归属批次隔离，不能根据case名称猜租户。此项是发布阻断条件。

## 6. 指标口径，必须先冻结

| 指标 | 推荐定义/必要证据 |
| --- | --- |
| 当前淹没面积 | 指定frame内达到产品湿阈值的有效单元面积并集；不把NoData计为干地 |
| 峰值淹没面积 | `max_t A(t)`；附峰值时刻，区别于全程受淹足迹并集面积 |
| 全程受淹范围 | 至少一次受淹单元的空间并集；不能与峰值面积互换 |
| 最大水深 | 指定区域和时间窗的max(h)，附位置/时刻与有效覆盖率 |
| 深度分级 | 使用同一frame或明确的逐格最大深度产品；建议区间 `[wet_threshold,0.5),[0.5,1),[1,2),[2,3),[3,+inf)`，阈值须经业务冻结，不自动等于求解器干阈值 |
| 到达时间 | 首次达到产品湿阈值的相对秒/区间；“未到达”“缺数据”“期初已淹”分开。输出间隔1h不能宣称分钟级精度 |
| 淹没历时 | 超阈值区间累计长度；断续受淹要累计。离散采样积分/插值、期初/期末截断和时间误差需冻结；现有接口尚无此产品 |
| 洪峰/分洪总量 | 洪峰为指定序列最大流量；体积按声明的插值/区间积分。输入洪峰、实际进入区内流量、累计进水和峰值库容不同 |
| 耕地/道路/房屋 | 资产与淹没范围真实相交；道路段去重，房屋明确占地/建筑面积；不以总淹没面积替代房屋面积 |
| 人口/村庄 | 人口快照日期、空间分配策略、行政区归属和跨区去重；报告未匹配/覆盖不足，不据面积比例擅自推精确人数 |
| 损失 | 必须有资产价值/基准年、损失函数/版本、币种与审查；缺少时NULL+NOT_COMPUTED，不从截图或通用比例填值 |

库与计算合同用SI：m、m2、m3、m3/s、s；显示层可换km2、ha、亩、万m3、亿元等，数值与单位分离、不把“8.100亿m3”存入数值列。1ha=10000m2，1km2=1000000m2，1亩=2000/3m2；小数舍入仅展示时执行。

地理数据保留源CRS、目标CRS、轴序和转换证据；不能把改SRID标签当坐标转换。RFC7946 GeoJSON接口使用WGS84经纬度顺序，源投影坐标另存，转换在批准的GIS输出适配层完成，不改变GeoTIFF Reader只读原值/掩膜的约束。[GeoJSON标准](https://www.rfc-editor.org/rfc/rfc7946) [PostGIS转换说明](https://postgis.net/docs/ST_Transform.html)

## 7. 当前能力和不能承诺的部分

能力要分四层：**原始变量存在 → 产品适配完成 → 质量验收通过 → 允许发布**。例如structured的首次到达原始变量存在，但尚不能据此宣布新业务API的到达图层AVAILABLE；本方案提出的新统一发布适配尚未实现。每种引擎、每种产品分别记录这四层，不能仅用一个“有模型”开关。

- structured小时流程能输出深度/水位/诊断速度、体积、湿面积、入出流/雨量、最大深度/速度、首次到达等，但属于填洼/连通传播和简化速度诊断，不应标成已通过真实工程认证的三角浅水结果。
- 实验三角路线已验收合成封闭域及限定Manning/降雨，原生time×face与structured的time×y×x不能混用。当前没有开放边界执行、完整到达/历时产品；逐面速度可由湿面动量/深度定义派生，但还需专门适配和干湿/单位验证，不能宣称已有发布产品。
- 当前社会经济关联有准备/审计契约，未形成正式受灾人口、经济损失和避险路径计算成果。第一期可以接入受信外部结果并保留来源，不能直接置为MODEL_COMPUTED。
- 首期避险为人工/外部方案保存、容量与关联缺口检查、洪水风险提示。自动路径优化、撤离调度、真实指令下发需要数据和规则另行冻结，尤其不能以“模型里没水”推断现实道路安全。
- 三维先规划“同一二维结果的三维场景展示”；建筑内部、桥梁通行、垂向流速和真实3D水动力不属于本期。

## 8. 建议实施顺序

1. **R0 合同冻结**：页面字段目录、ID映射、指标口径、任务/发布状态、引擎能力矩阵、租户安全，人工评审后再写生产代码。
2. **R1 元数据与编排**：场景版本、run/attempt、输入快照、worker协议、文件索引与不可变发布；与当前G1关联，不动数值核心。
3. **R2 计算结果适配**：先导出已有可信产品，缺能力显式缺项；合成小数据验证汇总/帧/曲线/审计全链。
4. **R3 五页数据接入**：详情、结果、过程共用一个store上下文；避险接人工版本，三维接资源状态；彻底移除正式模式硬编码兜底。
5. **R4 风险与时空补充**：在资产来源、覆盖、统计阈值、到达/历时策略冻结后独立实现和验收。
6. **R5 高级能力**：开放边界真实场景、自动避险计算、可交互三维、工程率定与生产性能分别通过专项，不与“页面已接API”混作一项。

方案倾向先让链路可追溯、可重试、可审计，再逐项补产品。此建议不要求改选原已批准B路线；当前阶段也不要求用户重新选择A/B/C。

## 9. 尚需确认但不妨碍先做方案的事项

计算场景与旧预案文档的业务命名；哪些页面指标属于首期必需发布门槛；真实输入/人口资产/安置点数据责任人及版本；湿阈值与到达/历时统计规则；业务部署的文件服务和任务执行设施；租户/项目授权模型；金仓具体版本与模式。实施前应列成有默认建议和影响范围的决策表，不能由实现模型静默猜值。
