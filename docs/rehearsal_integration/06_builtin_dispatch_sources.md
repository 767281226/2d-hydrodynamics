# 内置历史调度与扩展模板的来源方案

核查日期：2026-10-19。用途：内置**公开报道历史事件库、可克隆场景模板及缺项清单**，不是正式调度令库，也不是已经率定的完整历史洪水计算包。

## 1. 内置范围与状态

主模板名称建议“天津海河23·7洪水：东淀启用与调度回顾（公开资料版）”，保留别名“2023.7.31洪水调度方案”。不能把7月31日当作所有闸门或蓄滞洪区实际启动时刻。官方回顾记载东淀启用决定生效于2023年8月1日2时。[S1](https://www.tj.gov.cn/sy/tjxw/202308/t20230828_6386701.html)

初始模板状态为 `PUBLIC_HISTORY_PARTIAL`：可浏览、检索、克隆为草稿，`engineeringValidated=false`、`runnable=false`。缺少完整边界过程、地形/工程版本、雨量、初值、规则原始证据和下游条件时，不能把“内置”标成“可直接复演”。所有数值成果卡默认NULL，不带演示包中的8.35m、307.5km2等固定结果。

2023历史主模板的启用事件只绑定东淀；不得由界面的“东淀和文安洼”组合名称推断文安洼同年也实际启用。文安洼是否运用及方式必须有独立资料，未核定保持未证实。永定河泛区属于另一子场景，不能将其来水观测放到东淀边界。

## 5. catalog字段与导入规则

每来源：sourceId、title、publisher、originalPublisher、URL、publishedAt及precision、accessedOn、retrievalStatus、excerptLocator、sourceClass、reviewStatus。短释义即可，不复制完整新闻文章；未取得原始文件时contentHash为空，不伪造SHA。

每事件：eventKey、template/scopeAliases、eventType、eventTimeLocal或null、timePrecision、rawTimeText、normalizationPolicy、sourceTimezoneExplicit、reportedAt、measurements及unit/datum、sourceRefs、evidenceStage、missingFields、canDriveModel=false、gateCommandsSent=0。如果某事件有决策和观测两个语义，按独立事件/关联证据拆分，不以同一flag泛化。

sourceRef必须存在，URL/标题/发布日期与来源记录对应。首批允许来源为已核正文的S1-S4；候选资料采用REVIEW_PENDING，不混进已核种子。scopeAlias先由业务字典映射到真实ID，映射未完成阻断计算；不能因两个名称相似就绑定。

内置模板的来源质量与运行准备度是两个维度：公开历史可以已核但缺完整计算输入；纯合成模板可以可测试但不是历史事实。前端列表分别显示“公开资料版/人工情景/实验合成”“待补数据/可计算/结果已发布”。

每次更新catalog生成新版本与变更摘要；用户已克隆的版本不自动更新。合成验收必须覆盖未明确时区、日期级精度、报道晚于事件、观察值被误当动作、文安洼/东淀范围混淆、预测被误当完成和待核来源被误启用。
