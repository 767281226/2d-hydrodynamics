# 方案管理显示与新建输入补充

日期：2026-10-19。依据用户最新两张截图及本地演示代码，补充到[总体方案](01_solution.md)。本补充优先于早期草案中将下边界当作普通用户待填参数的表述。

## 1. 总体页面显示

只读源码复核补充：业务 `RehearsalPlanCreatePanel.vue`、`planCreate.js` 与 `ForecastPlanListPanel.vue` 仍处原型链路。列表“推演时间”实际按createdAt筛选，收藏/删除只改本地数组；新建只toast后关闭，没有真实保存。新建预览固定逐小时，未使用outputStepMinutes或forecastPlanId；initial/rain有页签定义却无内容。下边界虽然是占位UI，draft仍隐含3.2/3.48/3.85m三个默认值。这些默认值必须排除于新合同/提交快照，不能因隐藏页签而继续送入模型。

正式业务保留已有 `/flood/rehearsal` 页面，不在压缩演示包中开发。整体布局包括：方案管理列表、当前方案概要、五个结果面板、地图/图例/时间轴、任务状态与质量提示。

### 管理筛选与列表

| 要素 | 合同与行为 |
| --- | --- |
| 推演时间范围 | 默认筛选模拟开始时间，不混用创建时间；日期输入转Asia/Shanghai的左闭右开范围。若另支持时间窗相交查询，显式提供timeFilterMode，不偷偷换含义 |
| 推演对象 | 基础区域ID/多区组合scope，名称仅显示；支持全部，不从当前地图中心推范围 |
| 方案状态 | 全部、草稿、待补数据、排队、计算中、后处理/发布中、可查看、失败、取消、归档；“可查看”不是工程验收通过 |
| 名称检索 | 非空白标准化，按后端安全查询；回显关键词；不拼SQL或让通配符越权 |
| 收藏过滤/星标 | 用户自己的收藏，和内置模板收藏分开；多用户不会相互取消 |
| 总条数/更多 | 服务端分页和权限过滤后的总量；不能写死2条；查询条件变化回第一页 |
| 排序 | 显式字段/方向白名单，默认最近更新；稳定ID作为次排序避免翻页重复 |
| 空/失败/加载状态 | 暂无方案、无匹配、无权限、网络失败分别提示；失败不显示mock方案 |
| 新建入口 | 可空白新建、从内置模板克隆、复制已有版本；模板不原地改写 |

每张卡片至少包含：scenarioId/versionId、名称、推演对象、事件/开始时间、时长、创建类型、创建时间、收藏状态、运行状态、所展示resultSetId及计算完成时间。三项结果卡值：`peak_storage_volume`、`maximum_depth`、`peak_inundation_area`，均带scope/口径/单位/来源/质量。

无已发布结果时三项值为NULL并显示未计算，不能显示0，也不能显示模板的旧峰值。正在重算时可以显式提示“另有旧结果可查看”，但当前版本卡片不静默替换为旧版本数据。8.100亿m3等展示字符串只由SI数值格式化生成；显示精度不代表源数据精度。

卡片操作：

- 查看方案：草稿可看输入和缺项，已发布版本可看结果；总是带version/run/result选择上下文。
- 三维仿真：仅当同结果集有可发布三维展示资源才可进入；否则说明不可用，不展示静态PNG冒充计算。
- 删除：用户场景先逻辑归档/删除，保留历史引用和审计；运行中的任务须先处理取消，不能删除文件使worker写到悬空目录。内置模板本体不可由普通用户删除，可取消收藏/隐藏或克隆。
- 复制/新版本/重新计算：三种不同动作。复制创建新scenario；修改冻结输入创建新version；同版本人工重算新run；技术重试同run新attempt。

### 地图与概要

顶部保留当前方案、版本、区域、结果来源、模拟时间范围和状态。地图图层、站点/闸门标记、工程设计属性、规则时间轴与结果指标分别来自其对应的版本化数据源。点击标记返回稳定对象ID、关联来源与缺项，不用名称拼接结果。

五个面板、图例和时间轴共用resultSet/scope/frame。统计范围不随地图缩放自动改变。全程最大、当前时刻、设计指标用不同标签；跨区域缺覆盖必须可见。取消/失败/仅历史展示时也能查看已保存输入，但没有数值产品的控件禁用。

## 2. 新建方案基本输入

| 字段 | 必填与默认 | 校验/解释 |
| --- | --- | --- |
| regionIds/scopeId | 保存方案必填 | 从当前推演对象带入但允许授权范围内修改；修改后重查断面/规则/输入覆盖 |
| name | 保存必填 | 建议1至128字符、去首尾空白；同租户可同名但ID独立，复制带后缀 |
| description | 可选 | 建议最多2000字符，纯文本或受控富文本；不能夹带可执行脚本 |
| creationType | 服务端赋值 | MANUAL、BUILTIN_CLONE、COPY、SYSTEM_RECOMMENDED；推荐不等于批准 |
| templateId/version | 从模板创建时必填 | 引用不可变模板，记录哪些字段被人工覆盖；原模板只读 |
| timeOriginLocal/timeZone | 可存草稿缺失；计算要明确 | 业务空格格式，Asia/Shanghai；普通新建可建议当前时间但保存为用户确认值，历史模板不能自动覆盖成今天 |
| durationHours | UI建议120h，可修改 | 有限正数；内部规范durationS。历史资料全程可能超120h，不把UI默认当历史事实 |
| outputStepMinutes | UI建议60min，可修改 | 有限正数，是结果输出间隔，不是求解器积分dt；内部规范秒 |
| outputTimesS | 后端预览生成 | 从0含精确终点；120h/60min为121个输出时刻。非整除追加终点，不越过窗口；满足引擎最小间隔/数量与源项断点约束 |
| inputProfileId/engineMode | 从区域已配置profile带入 | 包含地形/网格/初值/糙率/数值方法版本；不让普通用户重填一次性资料，仍展示版本和缺项 |
| requestedProducts/metricPolicy | 采用已冻结产品profile | 必需与选配分开；不支持必需产品则预检阻断，不能静默降级 |

保存草稿仅要求最少业务信息合法；冻结/计算要求运行字段完整。后端返回fieldErrors、missingInputs、unsupportedCapabilities，而不是只有“参数错误”。物理量上限采用实际引擎合同和资源预算，不为UI编造新的物理范围。

输出时刻预览须展示帧数和数据规模估计。对源项断点，不允许前端偷偷改原雨量时刻；可以由后端提出需增加的输出时刻，用户确认后写入新版本。资源超预算时阻断计算但仍可保存。

## 3. 上边界洪水：按断面独立选择来源

不能把界面中的“大清河台头镇西”“中亭河xx断面”直接当作有效主键；先关联真实断面ID、位置、所属区域、CRS/高程基准和输入角色。无真实编码的xx占位符只能用于demo。

每个断面保存单独的sourceMode、sourceDatasetId/version、quantity、unit、timeBasis、temporalPolicy、dataQuality和coverage。切换断面不共享同一条默认曲线；切换来源前保留/提示未保存修改，不静默覆盖人工值。

| 来源模式 | 必需信息 | 不允许的替代 |
| --- | --- | --- |
| FORECAST 预报成果 | 预报方案/模型/发布批次、发布时间、预报起点/有效期、断面匹配、原始序列、版本与质量 | 下拉选名称后仍使用页面默认折线；把未来预报当历史实测 |
| DESIGN 设计洪水 | 设计成果/审批或依据版本、重现期/频率及互斥校验、设计方法、断面、完整过程线/单位、时间平移策略 | 只填“20年一遇”就自动生成任意洪峰；把设计洪水记为2023实测 |
| HISTORICAL 历史洪水 | 事件ID、站点/断面ID、观测/整编/重建类别、原时区和时间窗、逐点质量、缺测与完整过程线 | 将报道中的单点流量/洪峰/总量插值成完整实测过程 |
| MANUAL 人工设定 | 明确人工情景标识、时间-值表或导入文件、输入者与依据、原单位、插值/分段策略 | 默认折线未确认即当输入；非法值裁零、缺段自动填0 |

图/表展示同一份规范序列，编辑表后曲线同步，曲线导入不得只有截图。前端图形只读预览不改变数据；若允许拖点编辑，必须以MANUAL派生版本保存。时间单调且唯一，值有限；Q采用幅值与direction分开，不能用负Q偷偷表达另一种边界。重复时间冲突、缺口、窗外点、单位错误明确定位。

内置2023事件库可以填充历史事件/调度说明，但不能替代缺失的台头/中亭河连续水文输入；选择后页面应展示已具备与仍缺资料。

## 4. 工程运用规则与降雨

规则选择复用现有调度规则/联合调度模板，冻结版本与条件、阈值/单位/基准、工程ID、批准状态和适用范围。用户可选择“仅展示历史调度”“固定人工情景操作”“规则建议评价”等语义；首期不提供实际指令下发。定时/阈值/联合规则的优先级、冲突、重复事件与同刻动作顺序必须显式规定，不由数组顺序碰运气。

当前自定义工程表含controlMethod、dispatchRule、controlFlow(m3/s)、openingHeight(m)、remark。openingHeight是米，不是G1的openingRatio；只有工程资料提供并明确采用最大开度等换算依据时才可转换，否则分别保留且不计算比例。预设启用/退洪静态文案同样不能充当真实规则和动作参数。

公众报道中的启用/退水记录默认 `EXTERNAL_REPORT`，不是可直接执行的gate command。开度比、闸口数、流量和扒口宽度分别保存；缺值为NULL。没有已批准的结构物模型时，闸门开度/破堤参数只能作为情景注记或审计输入，不自动变成求解器RHS。

雨量虽然未出现在截图首屏，仍需在新建“降雨/高级输入”中明确：不考虑降雨、引用均匀分段常值雨量、待补。草稿可以待补；计算时不得把未知雨量视作零。来源单位mm/h或m/s独立适配，缺测不填零。公开报道的全市累计雨量不能直接摊成区域均匀逐时雨量；从上下游Q已含的流域产流再叠加同一雨量还须检查是否重复计入。

## 5. 下边界不作为用户输入：有条件的后台策略

按用户最新要求，隐藏/移除普通新建页的“下边界设置”编辑页签；不把它列为保存方案的必填项。后端仍保留 `downstreamPolicy` 与来源，不能删除物理语义。

默认：`mode=DEFERRED_UNKNOWN`、`userInputRequired=false`、`applied=false`。这不是Q=0、水位=0、封闭墙或自由出流。

| 情形 | 系统行为 |
| --- | --- |
| 历史事件浏览/保存草稿 | 允许，不要求下边界；不生成数值结果 |
| 区域已有经过核验的固定输入profile | 后台绑定具体profile及边界序列/规则版本，条件是范围、时段、变量/单位/基准、引擎能力全部匹配；向用户展示只读依据 |
| 仅小型合成封闭域测试 | 显式 `SYNTHETIC_CLOSED_DOMAIN` 且原生配置closed_wall；不能拿这个策略代表真实东淀下游 |
| 真实开放域计算需要下游条件，但资料未知 | 保存允许，`canCompute=false`，返回DOWNSTREAM_DATA_UNRESOLVED；不让用户被迫填一个猜值 |
| 资料有了但引擎未实现开放边界 | ENGINE_CAPABILITY_UNSUPPORTED；不能将资料标为实际应用 |

后续可自动选用的条件必须来自已核验的水位/流量时序或已批准边界模型，并通过独立验收；本轮没有证据支持给真实工程自动设置恒定水位、正常水深或自由出流。用户授权由协调方处理常规条件选择，不等于授权捏造未知物理。

## 6. 新建提交体验与持久化

推荐提供“保存方案”和“保存并校验计算”两种动作。后者先冻结输入，再预检：满足条件才创建run，否则保留方案、清楚列出待补项。不能因为缺水文资料而让用户完全无法建方案，也不能显示“已计算”来掩盖未运行。

创建请求带Idempotency-Key；重试不会复制方案/run。保存与冻结/排队之间要有明确状态和事务/恢复语义。取消编辑只丢未保存草稿，不取消另一个已排队任务；有修改时确认离开。提交中禁用重复按钮，后端仍需幂等。

字段落库：scenario保存业务身份/收藏外键；version保存表单规范值、原单位/展示值与来源快照；input_series/point保存各断面曲线；ruleSnapshot保存规则引用及不可变内容；downstreamPolicy保留未知状态及条件绑定；run只在通过预检后创建。截图布局变化不应改变底层数据合同。

## 7. 新增验收场景

- L01：推演时间和创建时间不同，筛选按显式语义正确；分页总量、收藏、租户各自隔离。
- L02：模板无结果卡片不显示截图峰值；有旧结果/新版本时不串数；内置模板不可原地删除。
- C01：120h/60min生成121帧；非整除终点正确，输出步长不进入求解器积分dt参数。
- C02：不同断面使用不同来源/时序，切换不会丢数据或复用同一曲线。
- C03：预测批次过期、历史时窗不足、设计洪水只给重现期、人工缺段均产生具体门禁，不自动补线。
- C04：图表值、提交序列、单位换算和摘要一致；非法/重复/非有限数据拒绝。
- C05：下边界未知可保存，不能自动改成零或closed_wall；可信profile可绑定但未支持的引擎仍拒绝。
- C06：历史模板保留历史日期，不能被当前日期默认值覆盖；历史事件和计算时间窗外事件独立显示。
- C07：未知雨量与明确无雨区分；累计雨量不自动摊平；规则不能自动执行闸控。
- C08：重复点击、失败重试、取消编辑、并发版本更新、克隆模板均可追溯且不产生重复运行。
