# Triangular business-input preparation (P3-A)

This independent preparation path binds three business inputs to an accepted
P0–P2 UGRID mesh: Manning roughness on faces, initial depth/absolute level on
faces, and group-level forcing on actual exterior edges. It writes a JSON
preparation package (`triangular-business-preparation-v2`) that references the
UGRID mesh artifact and records its mesh ID, actual topology fingerprint,
semantic `terrain_fingerprint`, CRS and ordered stable face IDs. The terrain
fingerprint covers elevations, validity, coverage/areas, units and datum
provenance, so either the reader or writer rejects a changed or mismatched
linked terrain artifact. Legacy v1 packages lack that content binding and are
explicitly rejected; regenerate them instead of inferring a trusted digest. It never
creates solver arrays, divides group discharge into edge fluxes, or runs a
solver.

P3-A deliberately supports constant values and explicit face-ID assignments.
Raster roughness aggregation, socio-economic source-face intersections and
native triangular GIS output remain P3-B work because they need their own area
aggregation contracts.

## Run the synthetic example

Install the base triangular extras and prepare the example mesh/terrain first:

```text
pip install -e ".[triangular]"
python -m hydrodynamics.mesh_preparation examples/triangular_mesh/preparation.yaml
python -m hydrodynamics.triangular_business examples/triangular_mesh/business_preparation.yaml
```

The first command writes `examples/triangular_mesh/prepared_mesh.nc`; the
business command then writes `business_preparation.json` beside the YAML. The
example contains constant roughness, explicit depth assignments for selected
stable face IDs, a total-discharge time series on the outer boundary, and a
water-level boundary on the hole ring. Both files are synthetic fixtures.

The console entry point is `hydrodynamics-business-prepare`. The Python API is
`prepare_triangular_business`; the package reader is
`read_triangular_business_package`. The emitted JSON sets
`preparation_only: true` and `simulation_result: false`.

## Strict YAML inputs

The typed schema is `TriangularBusinessConfig`; its JSON Schema is generated by
`TriangularBusinessConfig.model_json_schema()`. Unknown keys and implicit
coercions are rejected. Paths are relative to the YAML file. `mesh_file` must
refer to a P2 UGRID preparation artifact and `output_file` must not overwrite
it or the config.

| Input | Type | Unit | Default/required | Legal range and error |
| --- | --- | --- | --- | --- |
| `version` | integer | — | default `1` | exactly `1`; other versions fail |
| `mesh_file` | string path | — | required | non-empty relative path; linked file must be a valid preparation UGRID |
| `output_file` | string path | — | required | non-empty relative path; cannot alias the config or mesh file |
| `roughness.type` | `constant` or `face_values` | — | required | selects exactly one roughness source mode |
| `roughness.manning_n` | number (`constant`) | 1 (dimensionless, matching the existing project contract) | required | `0 < n <= 1`; non-finite, zero, negative and above-range values fail |
| `roughness.assignments[]` | `{face_id: integer, manning_n: number}` (`face_values`) | ID dimensionless; value unit 1 | required, one or more | each ID must exist on the referenced mesh, be unique, and have `0 < n <= 1`; unassigned faces remain invalid/masked |
| `roughness.source` | string | — | required | non-empty provenance label |
| `initial_condition.type` | `constant` or `face_values` | — | required | selects exactly one initial-field source mode |
| `initial_condition.quantity` | `depth` or `level` | — | required | reuses the existing initial-condition meanings |
| `initial_condition.value_m` | number (`constant`) | m | required | finite; depth must be `>= 0`; absolute level may be below zero in its datum |
| `initial_condition.assignments[]` | `{face_id: integer, value: number}` (`face_values`) | ID dimensionless; value m | required, one or more | unique IDs must exist; depth values are `>= 0`; unassigned faces remain invalid/masked |
| `initial_condition.vertical_datum` | string or null | — | default `null` | `level` inherits a known terrain datum when omitted; a supplied datum must match terrain; depth may carry a matching declared datum |
| `initial_condition.source` | string | — | required | non-empty provenance label |
| `boundary_bindings` | array | — | default `[]` | group names must be unique; bound edge IDs may not overlap between bindings |
| `boundary_bindings[].type` | `constant` or `timeseries` | — | required per binding | selects one value mode |
| `boundary_bindings[].group_name` | string | — | required | must name an existing `boundary_groups` entry; internal constraints cannot be used |
| `boundary_bindings[].quantity` | `discharge` or `water_level` | — | required | discharge means total for the whole group; no edge allocation occurs |
| `boundary_bindings[].value` | number (`constant`) | m3/s or m | required | finite; discharge is `>= 0`, absolute water level may be negative |
| `boundary_bindings[].time_s` | number array (`timeseries`) | s elapsed from start | required, non-empty | finite, non-negative, strictly increasing, and same length as `values` |
| `boundary_bindings[].values` | number array (`timeseries`) | m3/s or m | required, non-empty | finite; discharge is non-negative, absolute water level may be negative; same length as `time_s` |
| `boundary_bindings[].vertical_datum` | string or null | — | default `null` | required for water level and must equal known terrain datum; forbidden for discharge |
| `boundary_bindings[].source` | string | — | required per binding | non-empty provenance label |

All face assignments are keyed by stable `face_id`, never by a caller-provided
array reshape. The package records the actual face ID order and SHA-256 topology
fingerprint. It also records a semantic `terrain_fingerprint` over ordered
elevations, masks, covered/valid areas, coverage, units and datum provenance.
The writer checks the package object against the linked UGRID before writing;
the reader checks the same content on readback. Unknown IDs, stale topology or
terrain fingerprints, changed CRS, mesh ID or face ID order are rejected.
Package format v2 requires `terrain_fingerprint`; legacy v1 packages are
rejected with a regenerate instruction instead of receiving a digest silently.

Before hashing, terrain elevations, areas and coverage ratios are normalized to
floating-point numbers to match UGRID storage. Equivalent inputs such as `10`
and `10.0` therefore retain the same fingerprint through a file round trip.
Missing elevations remain `null`, masks remain boolean, and face IDs retain
their integer representation.

## Field semantics

### Roughness

In `constant` mode, every face must be valid and every effective coefficient
must be identical. In `face_values` mode, only supplied IDs are valid and may
have different values; the reader rejects payloads that contradict the mode.

`manning_n` retains the existing structured-input convention documented in
`docs/input_parameters.md`: a dimensionless coefficient (unit `1`) with range
`(0,1]`. P3-A does not rescale or reinterpret structured values. Constant
roughness marks all mesh faces valid. Face-ID assignments only mark
listed faces valid; omitted faces use JSON `null` and `valid_mask: false`, never
zero. Each field records its source label and mesh identity.

### Initial state

`depth` is water depth relative to mapped terrain, in metres, and is
non-negative. `level` is absolute water-surface elevation in metres and needs a
known terrain vertical datum; when the config omits a separate label, that
known terrain datum is inherited, and any supplied datum must match exactly. When no
separate datum is supplied for a depth field, an available terrain datum is
retained as provenance. Constant depth values must be identical on all valid
terrain faces, and the constant field mask matches the terrain mask. An initial assignment cannot mark a face valid where
its terrain face is invalid. Missing face IDs remain masked rather than being
filled.

### Boundary groups

A binding resolves its group to the exact P2 boundary edge indices and
node-pair endpoints and serializes both. A group found only in
`constraint_groups` is rejected; a name present in both boundary and constraint
mappings is ambiguous and rejected. The discharge series is a **total group
discharge** in m3/s; this layer does not divide it among edges or decide
physical inflow/outflow signs. Water level uses metres and a matching vertical
datum. Time samples are stored as supplied in elapsed seconds, with no
interpolation, extrapolation, resampling or time integration. Finite negative
absolute water levels are valid in their declared datum; discharge values
remain non-negative to preserve the existing structured boundary contract.

The reader checks group membership against the referenced mesh and rejects
duplicate group bindings or any edge assigned by two bindings. An overlapping
boundary group is allowed on the mesh contract itself, but assigning the same
edge twice in one business package is an error.

## Deferred work

P3-B still needs source-face/target-face intersection records, area fractions,
aggregation rules for total versus density fields, duplicate/partial coverage
policies, approval/provenance handling, and triangular GIS export. No values are
copied across faces without a field-specific aggregation decision.

P4 remains a later design decision for each solver path. This package does not
create numerical fluxes, edge allocation, source terms, wet/dry state, time
steps or simulation results. The existing structured workflow and solver do
not accept this package as a calculation input.
